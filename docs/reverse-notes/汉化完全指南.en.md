## The three font paths (the central finding)

Everything else in the record follows from this table:

| UI surface | Font asset | Format | CJK capacity |
|---|---|---|---|
| Dialogue, subtitles, HUD | `english_18` / `english_20` | UCFX `INFO/CHAR/MTRL` | **expanded from 271 to 4,134 glyphs**, atlas 2048×2048 — Chinese renders correctly |
| Pause menu, PDA text | `fonts_enext` | CFX (GFx font record) | 486 glyphs total, only **82** spare Latin-extended slots; reused 52 |
| Options, part of the menus | `SHELL.gfx` embedded `Times New Roman` | `DefineFont3` inside the Scaleform movie | 114 codepoints, **5–6** usable |

`fonts_enext` and the movie font have no CJK glyphs, so Chinese fed to them renders as tofu boxes. **The number of boxes always equals the number of Chinese characters** — that identity is what made the §54 diagnosis possible (`ON`/`OFF` → one box each, because they had been translated to the single characters 开/关).

## Why growing the font fails where it fails

- A larger atlas is accepted by `FontTextureInfo` (§22, §35) — so the *reader* is not the limit.
- But editing `SHELL.gfx`'s atlas crashes (`0x874640` when the atlas grows, `0x6D057C` when only pixels change, §47) even though every static check passes: chunk layout, ASET, CSUM, compression segment count.
- Conclusion recorded in §51: the movie path is not editable at the WAD layer; only text-level changes are safe there.
